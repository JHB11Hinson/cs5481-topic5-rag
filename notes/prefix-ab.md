## Protocol

- **Pairing.** One `contextual_prefix` cell against its `plain` twin: same chunk strategy, same retrieval mode, same generator, same golden set. The two resolved configs are diffed (`baselines.substantive_diff`) and the pair is refused unless `contextualization` is the only factor that moved.
- **Recomputation.** hit@10, MRR, nDCG@10, citation precision/recall, span hit rate and the abstention counts are recomputed from `predictions.jsonl`, `chunks.jsonl` and `citations.jsonl` with the same rule the matrix uses (a hit is the golden quote found inside a returned chunk; a citation counts when the verifier located the quote).
- **Paired test.** McNemar's exact test, two-sided, on the discordant items: `b` = the prefix got it right and plain did not, `c` = the reverse. Implemented once, in `aggregate.mcnemar_exact`, and called through `baselines.mcnemar_counts`.
- **Interval.** 10000 bootstrap resamples, seed 20261030, percentile interval, 95% confidence. The resample unit is the **item** (a golden question), not the claim: an item's whole claim batch travels with it.
- **Missing is not zero.** A twin whose run directory is absent, unfinished (no `metrics.json`) or measured on another golden set leaves its pair `pending`, with the reason printed and no metric attached.
- **The strings themselves are audited elsewhere.** `notes/prefix-audit.md` reads 20 of the generated prefixes against a four-part rubric (0 of 20 fail); this note measures their effect on retrieval and citation, not their quality.

## One asymmetry a reader must not mistake

At `contextual_prefix` the **dense and the sparse indexes both carry the prefix, while the generation prompt does not** (`ADR-0013`): the prompt is handed the raw chunk text. The generator therefore never sees a prefix, so no citation number below is the model reacting to one. Citation precision can still move, because which chunks reach the prompt -- and at what rank -- is decided by the prefixed index. Read every citation delta in this note as **a retrieval effect**, and read the cost row beside it as the reason the prompt was left alone: the money per question barely moves, because the tokens sent to the generator are the same tokens. A second experiment that does put the prefix in the prompt is possible without touching the index code (`chunks_contextual.jsonl` keeps prefix, contextual text and original text side by side), and this build does not run it.

A second thing worth keeping straight: the prefix costs one cheap-model call per chunk **once**, and every run above reports a full prefix-cache hit (`prefix_cache_hits` in `cache_stats.json`), so the A/B compares two retrievals over the same cached strings rather than two samples of generated text.
