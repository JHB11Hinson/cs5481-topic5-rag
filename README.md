# CS5481 Topic 5 — Grounded Documentation QA

Question answering over a pinned documentation corpus where every claim carries a citation a program can check, and the system says so when the documentation does not answer.

Course brief: `docs/course-brief/CS5481_Project_2026-1.pdf`. Read `AGENTS.md` first for the graded constraints, `GLOSSARY.md` for the vocabulary used in every ticket and ADR, and `docs/adr/` for the decisions behind the design. The live picture — numbers, gateway quirks, next moves — is in `docs/PROGRESS.md`.

## What this is

A RAG system over Vault 1.21.x documentation, pinned by commit (`ADR-0008`), with three experimental factors:

- **Chunk strategy** — a fixed 512-word window, or a recursive splitter that keeps tables and code fences whole and groups children under parents.
- **Retrieval** — dense bge-m3, hybrid (dense ∥ BM25 fused with RRF), or hybrid plus a cross-encoder reranker.
- **Contextualization** — plain chunks, a generated one-sentence contextual prefix indexed alongside each chunk, or late chunking (whole-document encoding, per-chunk span pooling).

Eighteen cells of that grid run through one pipeline, each writing an immutable `runs/<run_id>/` directory. Answers are generated by a hosted model that must cite a chunk and quote it verbatim; citations are verified by string search first, then by a local NLI cross-encoder and a hosted judge whose agreement with 30 hand-labelled claims is measured.

When retrieval cannot support an answer the system says so — and the flag `generate.ungrounded_answer` decides whether that is the whole reply (`abstain`, the default and the only value any measured cell uses) or a fixed gap note followed by the model's own labelled answer with no citation (`assist`, what the demo serves). `answer_mode` on every answer carries which of the three states a reader is looking at (`ADR-0020`).

## Run it

Requires Python 3.9+ with `pyyaml` and `numpy` for the stub path; the real path adds `torch`, `sentence-transformers`, `transformers`, `qdrant-client`. Credentials come from `.env` (`LLM_BASE_URL`, `LLM_API_KEY`, `LLM_SESSION_HEADER`) — see `.env.example`.

```bash
python -m ragqa.selftest                                 # unit tests, no network
python -m ragqa.run --config configs/smoke.yaml          # offline stub path, ~10 s
python -m ragqa.run --config configs/ctx-plain.yaml      # real models, needs .env
python scripts/warm_prefixes.py --config configs/ctx-prefix.yaml
python -m ragqa grid check configs/grid                  # the 18-cell declaration
python scripts/run_matrix.py                             # resumable; skips finished cells
python -m ragqa aggregate --runs runs --out reports      # every table and figure
python -m ragqa serve --config configs/grid/cell-recursive_parent_child-rerank-plain.yaml
```

Set `HF_HUB_OFFLINE=1` and `TRANSFORMERS_OFFLINE=1` when the models are already cached: a hub check on `from_pretrained` can hang a run at 0% GPU, which looks exactly like a deadlock.

## Conventions worth knowing before editing

- A configuration never becomes a branch. Ablations differ by YAML, and the code baseline is pinned by commit (`ADR-0003`). A run directory without `metrics.json` is not a run; the pipeline deletes its own partial output rather than leaving a lie on disk.
- Retrieval hits are decided by locating the evidence quote in the returned chunk text, never by comparing chunk ids (`golden/SPEC.md`).
- Unimplemented stages raise. Nothing silently degrades to a simpler mode, because two cells that quietly became identical would be invisible in the results table.
- Wall-clock numbers go in `timings.json`; `metrics.json` stays deterministic.
- Adding a key to `ragqa/config.py`'s defaults changes every resolved-config digest, which is how a finished cell is recognised on resume. Change it between matrix runs, never during one.
