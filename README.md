# CS5481 Topic 5 — Grounded Documentation QA

Question answering over a pinned documentation corpus where every claim carries a citation a program can check, and the system says so when the documentation does not answer.

Course brief: `docs/course-brief/CS5481_Project_2026-1.pdf`. Read `AGENTS.md` first for the graded constraints, `GLOSSARY.md` for the vocabulary used in every ticket and ADR, and `docs/adr/` for the decisions behind the design. The live picture — numbers, gateway quirks, next moves — is in `docs/PROGRESS.md`.

## What this is

A RAG system over Vault 1.21.x documentation, pinned by commit (`ADR-0008`), with three experimental factors:

- **Chunk strategy** — a fixed 512-word window, or a recursive splitter that keeps tables and code fences whole and groups children under parents.
- **Retrieval** — dense bge-m3, hybrid (dense ∥ BM25 fused with RRF), or hybrid plus a cross-encoder reranker.
- **Contextualization** — plain chunks, a generated one-sentence contextual prefix indexed alongside each chunk, or late chunking (whole-document encoding, per-chunk span pooling).

Eighteen cells of that grid run through one pipeline, each writing an immutable `runs/<run_id>/` directory. Answers are generated by a hosted model that must cite a chunk and quote it verbatim; citations are verified by string search first, then by a local NLI cross-encoder and a hosted judge whose agreement with 30 hand-labelled claims is measured.

When retrieval cannot support an answer the system says so — and the flag `generate.ungrounded_answer` decides whether that is the whole reply (`abstain`, the default and the only value any measured cell uses) or a fixed gap note followed by the model's own labelled answer with no citation (`assist`, what the demo serves). `answer_mode` on every answer carries which of the three states a reader is looking at (`ADR-0020`).

## Run it

A fresh clone arrives with no environment, no `data/` and no `runs/`. Two of the commands
below work before anything is fetched, and they are the two that prove the checkout is
sound; everything after them needs data, models or credentials.

### Install

```bash
python -m venv .venv
source .venv/bin/activate          # Windows: .\.venv\Scripts\Activate.ps1
python -m pip install -U pip
pip install -e ".[dev]"
```

Python 3.9+. `.[dev]` is `pyyaml`, `numpy` and `pytest`, which is all the stub path and
`ragqa.selftest` need — `ragqa/config.py` imports `yaml` at module load, so nothing at all
runs before this step. Real cells add `torch`, `sentence-transformers`, `transformers`,
`qdrant-client` (`pip install -e ".[models,index]"`); the demo adds `chainlit` (`.[demo]`,
the default backend) or NiceGUI for `--backend nice` (`.[demo-nice]`).

Credentials come from `.env` in the working directory (`LLM_BASE_URL`, `LLM_API_KEY`,
`LLM_SESSION_HEADER`) — `cp .env.example .env` and fill it in. `ragqa/llm.py` reads the file
itself, so nothing is exported by hand.

### What runs where

| Step | Command | `data/` | models | `.env` |
|---|---|---|---|---|
| unit tests, no network | `python -m ragqa.selftest` | | | |
| offline stub cell, ~10 s | `python -m ragqa.run --config configs/smoke.yaml` | | | |
| the 18-cell declaration | `python -m ragqa grid check configs/grid` | | | |
| one real cell | `python -m ragqa.run --config configs/ctx-plain.yaml` | ✔ | ✔ | ✔ |
| prefix warm-up (hosted model only) | `python scripts/warm_prefixes.py --config configs/ctx-prefix.yaml` | ✔ | | ✔ |
| the whole matrix | `python scripts/run_matrix.py` | ✔ | ✔ | ✔ |
| every table and figure | `python -m ragqa aggregate --runs runs --out reports` | | | |
| the demo | `python -m ragqa serve --config configs/grid/cell-recursive_parent_child-rerank-plain.yaml` | ✔ | ✔ | ✔ |

`data/` is 322 MB of corpus, chunks, Qdrant index and embedding cache, git-ignored on
purpose (ADR-0003). Rebuild it from the pinned upstream tree:

```bash
python -m ragqa.ingest --ref 1817bdfe --clone https://github.com/hashicorp/web-unified-docs
```

or copy `data/` from a machine that already has it. Without it a real cell stops at
`data/corpus/vault-1.21.x-1817bdfe/docs_structured.jsonl` with a `FileNotFoundError`: that
is the expected first failure on a fresh clone, not a bug. `aggregate` without `runs/`
prints `PROBLEM no runs root at runs` and exits 1, while `reports/` is committed, so nobody
needs `runs/` to read a number — only to regenerate one.

### Offline flags

Set `HF_HUB_OFFLINE=1` and `TRANSFORMERS_OFFLINE=1` **after** both models are cached: a hub
check on `from_pretrained` can hang a run at 0% GPU, which looks exactly like a deadlock.
`scripts/run_matrix.py` sets both unconditionally (`setdefault`), so on a machine that has
never downloaded `BAAI/bge-m3` and `BAAI/bge-reranker-v2-m3` the first cell dies in the
embedder. Warm the cache once without them, then run the matrix:

```bash
unset HF_HUB_OFFLINE TRANSFORMERS_OFFLINE    # PowerShell: Remove-Item Env:HF_HUB_OFFLINE,Env:TRANSFORMERS_OFFLINE
python -m ragqa.run --config configs/ctx-plain.yaml
python scripts/run_matrix.py                 # resumable; skips finished cells
```

## Conventions worth knowing before editing

- A configuration never becomes a branch. Ablations differ by YAML, and the code baseline is pinned by commit (`ADR-0003`). A run directory without `metrics.json` is not a run; the pipeline deletes its own partial output rather than leaving a lie on disk.
- Retrieval hits are decided by locating the evidence quote in the returned chunk text, never by comparing chunk ids (`golden/SPEC.md`).
- Unimplemented stages raise. Nothing silently degrades to a simpler mode, because two cells that quietly became identical would be invisible in the results table.
- Wall-clock numbers go in `timings.json`; `metrics.json` stays deterministic.
- Adding a key to `ragqa/config.py`'s defaults changes every resolved-config digest, which is how a finished cell is recognised on resume. Change it between matrix runs, never during one.
